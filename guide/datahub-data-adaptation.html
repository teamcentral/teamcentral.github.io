Data Adaptation ​

There are ways to adapt the data being read or written by the Common Model. For example, if one system displays data as a decimal number, but you want the data to show as a monetary value, you can transform that data as the Common Model reads and/or writes it. Adapting data is more likely to be done on the subscribing side, but it is possible to execute on both.

NOTE

Only available adaptation options will be displayed based on your configured Endpoints and Mapping Actions.

Advanced Tab ​

In the advanced settings, you can dictate when data gets transferred from the Common Model to other systems. For instance, on the subscribing side, you may want some functionality to only execute when a new record is created or only when data is updated. Also, data taken from the Common Model that is a string, but needs to be written to a Connector as a double or decimal value, changing the output, can be done here.

Transforms Tab ​

Transforms can be added to either subscribe or publish Mapping; however, they are more commonly used to modify the data being consumed by a system (on the subscribe side). Transforms can be strung together to manipulate data in multiple ways.

Transforms run in list order, and the Value Type setting on the Advanced tab is applied after all of them. That ordering matters whenever a transform produces your final wire format — see Value Formatting → Order of operations.

Transform Recipes ​

Worked examples for the transforms that take configuration. Each section below opens with how the transform behaves at the edges — what happens on no match, on a null, on the wrong type — followed by recipes you can copy. Every input → output pair shown was produced by the transform itself.

Leading and trailing spaces are trimmed

Transform fields drop leading and trailing whitespace when you leave them. A Delimiter of , is saved as ,, and a Replace Pattern can't be a lone space. Spaces inside a value are kept. In a regex, write \s or [ ] where you need a space at either end.

Regex Replace ​

Uses .NET regular expressions. Match Pattern finds the text, and Replace Pattern says what to put in its place.

  • Every match is replaced, not just the first. Anchor with ^ and $ when the pattern should describe the whole value.
  • No match → the value passes through unchanged, type included. A match always produces text.
  • In Replace Pattern, $1, $2… insert what each ( ) group captured. Use ${1} when a digit follows (${1}0), and $$ for a literal $. Leave it blank to delete the match.
  • Case-sensitive by default. Start the pattern with (?i) to ignore case.
  • Escape regex characters you mean literally: . matches any character, so \. is a period. The same goes for ( ) [ ] + * ? | ^ $ \.
  • Non-text values are converted to text first. A date becomes culture-dependent text like 3/9/2026 2:05:07 PM, so put a Formatting Template ahead of it to control that text.

Chaining: replace a placeholder with a real default

Source systems often send N/A, none, or - where they mean "no value". Two transforms in order:

  1. Regex Replace — Match (?i)^\s*(n/?a|null|none|-)\s*$, Replace (blank). N/A becomes empty; Nathan doesn't match and passes through.
  2. Default Value — Value Unknown. Fires on null or empty, so the blanked placeholder becomes Unknown.

Regex Match ​

Extracts part of a value. The thing to remember: it returns the first capture group ( ), not the whole match.

  • Wrap what you want to keep in parentheses. A pattern with no group returns an empty string, even when it matches. To return the entire match, wrap the whole pattern: (\d+).
  • Use (?:…) to group without capturing, so alternatives don't steal group 1 — see the PO recipe below.
  • No match → null, unlike Regex Replace, which passes the value through. Follow with Default Value if you need a fallback.
  • A full ISO timestamp read from JSON arrives as a date, not text, so text patterns like the month recipe below won't match it. Use a Formatting Template such as {0:MM} instead. A date-only string like 2026-03-09 stays text.

Formatting Template ​

Builds a string from one or more values with .NET composite formatting. Value Formatting is the full reference for format specifiers. The most important rule from it: a specifier like :D6 or :yyyy-MM-dd only applies to a real number or date — text passes through unformatted.

  • On a multi-property map, the inner maps arrive as {0}, {1}, {2} in the order listed.
  • A null or empty input is returned unchanged rather than rendered. A null inside a multi-property map renders as empty.

Chaining: format a value that arrives as text

When the specifier is ignored because the value is text, convert it first:

  • Number as text → Compute Expression Convert('{0}', 'System.Int32') → Formatting Template INV-{0:D6}. "42" becomes INV-000042.
  • Epoch milliseconds → From Epoch Time → Formatting Template {0:yyyy-MM-dd}.
  • Date string → Date Only (or Convert TimeZone to UTC) → Formatting Template.

More in Value Formatting → When the value is text.

Compute Expression ​

Evaluates an expression after substituting each value into {0}, {1}, … as text. On a multi-property map, the inner maps fill the placeholders in order.

  • Text values must be quoted in the expression: write '{0}', not {0}. Unquoted text is read as a column name and fails with Cannot find column. Single quotes inside the value are escaped for you, so O'Brien is safe.
  • Numbers and booleans are left unquoted: {0} * 2, IIF({0}, 'Yes', 'No').
  • A null becomes the word null. Unquoted, that is a real null, so IsNull({0}, 0) works. Inside quotes it becomes the text 'null'.
  • Division is never integer division: 7 / 2 is 3.5.
  • Substring here counts from 1, unlike the Substring transform, which counts from 0.
  • Other useful functions: IIF, IsNull, Len, Trim, Convert, LIKE (wildcards * or %), and IN (…).

Business Logic Map - Simple ​

A lookup table: if the value equals a Comparison, return its Return.

  • Matching is exact and case-sensitive against the value as text: A does not match a. A boolean compares as True or False, capitalized.
  • No match returns Else Return Value, or the value itself when Return Original Value is on. A null input never matches a Comparison and goes to the else branch.
  • The same Comparison can't be listed twice; the save is rejected.

Business Logic Map ​

Groups of conditions, each with a Return Value. Groups are checked in order and the first group that is true wins. Within a group, And binds tighter than Or. If no group is true, Else Return Value is returned.

Conditions are equality-only

The Operator on each condition is not currently evaluated. Every condition is an exact, case-sensitive equality test, whatever operator is selected. And because every condition tests the same value, And between two different values can never be true. In practice this transform maps several values to one result. Anything richer — not-equals, greater-than, contains — belongs in a Compute Expression.

Substring ​

  • Starting Index counts from 0.
  • Number of Characters must be set: at 0 the result is empty. A value shorter than requested returns whatever is there.
  • A Starting Index past the end of the value raises an error. If values can be shorter than your prefix, use Regex Replace instead.
  • It can't count from the end. For the last N characters, use Regex Match (.{N})$.

Whole numbers read from JSON

Round accepts decimals, doubles, 32-bit integers, and numeric text. A whole number read from a JSON payload (42, not 42.0) arrives as a 64-bit integer and raises Invalid input type. That includes a field that is usually fractional but sometimes whole, like 2.5 one record and 3 the next.

Keeping trailing zeros

The result is a plain number, so trailing zeros are dropped: 2.50 comes out as 2.5. When the target needs a fixed number of decimals, follow Round with a Formatting Template {0:0.00}.

Date Change ​

Each unit is added independently, and any unit can be negative. Months and years respect calendar length: Jan 31 + 1 month is Feb 28.

CSV to List and String Join ​

Inverses of each other: CSV to List splits one delimited string into a list, and String Join joins a list into one string.

  • CSV to List always drops empty entries. A new transform starts with Trim Items on and Make Distinct off.
  • String Join also accepts a JSON array that arrives as text, e.g. ["a","b"].

Default Value ​

Fires when the value is null or empty. A value of only spaces is not empty and passes through, so put a trim — Regex Replace ^\s+|\s+$ → (blank) — ahead of it if that matters. See also replacing placeholder values such as N/A.

JSON Contains ​

Returns true if the JSONPath selects anything, otherwise false.

  • The input must be a JSON object or array. JSON that arrives as text always returns false, so put Parse to JSON ahead of it.
  • An empty array selects nothing, so $.tags[*] doubles as a "has any items" test.

Overrides ​

Overrides allow you to define different connector properties based on operations (Create vs Update). For example, you may want a different mapping behavior on creating a new record vs. updating an existing record.
