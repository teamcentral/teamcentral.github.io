central config validate ​

Validate Central connector/endpoint config JSON and report every finding with a Formik-compatible path, message, and severity. Exits non-zero if any error-severity finding is present.

The document is deserialized into a DataServiceConfigInstance with the platform's own CentralSerializerSettings — the same round-trip the API uses — then its whole graph (DataSource, actions, RequestBuilder/MapGroup, PropertyMaps/InnerMapGroups, Children, DependentPublishers) is validated in one pass.

PRE-MERGE CAVEAT: committed templates are pre-merge fragments whose top-level (and sometimes child) id is blank; the platform assigns ids at merge/save time. By default this command seeds a placeholder id per blank endpoint so those templates validate exactly as a real save would see them. Use --raw to validate the file verbatim (blank ids will then be reported).

Usage ​

central config validate <paths>... [options]

Arguments ​

ArgumentDescription
pathsOne or more config JSON files, directories (recursed for *-template.json), or globs to validate.

Options ​

OptionDescriptionRequired
--jsonEmit findings as JSON (machine/agent/CI consumption) instead of the human-readable report.No
--rawValidate the document exactly as authored. By default (merged mode) blank endpoint ids are seeded with placeholder GUIDs to simulate the merge/save step, so committed pre-merge template fragments don't produce false "Id is required" / "Duplicate Ids" errors. Ignored with --as.No
--as <String>Validate each file as a FRAGMENT of this config type (e.g. MapGroup, PropertyMap, DataSource) instead of a whole DataServiceConfigInstance. Runs the same per-node validation the full graph would. Use --entity to anchor entity-aware rules.No
--entity <String>With --as: the CoreEntityType the fragment's maps resolve against (e.g. Invoice), so rules like busProperty-existence run. Omit to skip entity-aware rules (as happens mid-graph when unknown).No
--entity-subtype <String>With --as and --entity: the entity sub-type discriminator (e.g. Customer for Company).No

Examples ​

bash
# Validate a single template
  central config validate Templates/Netsuite/customer-b2b-template.json

  # Validate every committed config template (directory recurses for *-template.json)
  central config validate Central.Platform.Services/Templates

  # Emit JSON for an agent or CI gate
  central config validate Templates/HubSpot/contact-template.json --json

  # Validate exactly as authored (no id seeding)
  central config validate ./my-endpoint.json --raw

  # Validate a lone fragment (a hand-authored MapGroup) against an entity's schema
  central config validate ./item-filters.json --as MapGroup --entity Invoice
