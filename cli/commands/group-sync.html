central group sync ​

Set a synced group's members from a list of emails, matched to existing Command users.

Unmatched emails are reported and never created. A Managed group is refused: its members are edited in the platform. An empty result is refused unless --allow-empty, because a failed directory read looks the same.

Creating a group needs exactly one of --owner-customer-id <id> (a live Command customer) or --operator-owned (no customer owner: the platform operator's group). A group for TeamCentral, Inc. as a customer takes --owner-customer-id. A sync never changes an existing group's owner: either flag is optional then, and one that disagrees with the stored owner is refused.

Output is counts and user ids only; --show-emails adds emails, for an operator at a terminal.

A dry run unless --apply: the write is printed, and made only with --apply.

Usage ​

central group sync [options]

Options ​

OptionDescriptionRequired
--command-config <FileInfo>The Command DB's platform config (e.g. customerconfigs/AppSettings/centralconfig-prod.json).Yes
--group <String>The group's name.Yes
--members <String>A file of member emails, one per line, or '-' for stdin.Yes
--source <String>entra-graph or scim. Only used to create the group when none has this name.No
--tenant-id <String>With --source: the directory tenant the group lives in.No
--external-group-id <String>With --source: the group's id in that directory.No
--owner-customer-id <String>Creating the group: the Command customer that owns it. It may then grant only on that customer's environments.No
--operator-ownedCreating the group: no customer owns it; it belongs to the platform operator, so it may grant all environments.No
--allow-emptyAllow a sync that leaves the group with no members.No
--show-emailsName users by email as well as id. Off by default so a scheduled run's log holds no emails.No
--applyMake the write. Without it, it is printed and nothing is written.No

Examples ​

bash
# Mirror an Entra group, creating the Command group on first run
  az ad group member list --group <id> --query "[].mail" -o tsv \
    | central group sync --command-config centralconfig-prod.json --group "TeamCentral Admins" \
        --members - --source entra-graph --tenant-id <tenant> --external-group-id <id> \
        --operator-owned
