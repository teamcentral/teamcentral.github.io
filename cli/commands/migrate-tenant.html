central migrate tenant ​

Migrate a tenant's data between Cosmos (NoSQL API) and Mongo vCore.

Documents are copied verbatim — no typed hydration between read and write (PRD-2843).

Forward (--target AzureDocumentDb) runs a cutover's modes in order: copy online, ahead of the freeze; reads each written page back and compares it (--diff-file lists any difference); records each container's _ts mark when --marks-file is given delta copies documents changed since the marks and moves them forward; run once ahead of the freeze to shrink it, then again inside it reconcile in the freeze; deletes target documents no longer in the source. Skips a container whose counts match (copy and delta read back every write, so nothing can be missing), unless the source has a TTL or --scan-all is given. Where counts differ it refuses, printing target − source; re-run with --expect-deletes Container=N. NEVER run it once the target is live: its new writes are not on the source and would be deleted verify in the freeze; counts must match exactly, plus a parity sample A copy that stops part way saves its progress next to --marks-file; continue it with --resume. A stopped delta is simply run again: finished containers already have their new mark. Two source documents sharing an id across partitions fail the container: DocumentDB keys on id alone. Exit code 1 on any failed container.

Reverse (--target Cosmos) copies every document and re-counts; any count mismatch fails the run (exit 1).

Prerequisites:

  • The tool does not gate writes. Forward copy (and a delta ahead of the freeze) may run while the source is live; quiesce it for the in-freeze delta, reconcile, verify, and for the reverse.
  • Both connection strings must be reachable from the host running the command.
  • target must already exist (cluster + database). The tool does not provision.

Usage ​

central migrate tenant [options]

Options ​

OptionDescriptionRequired
--cosmos-connection-string <String>Cosmos (NoSQL API) connection string. Source for --target AzureDocumentDb, target for --target Cosmos.Yes
--vcore-connection-string <String>Mongo vCore connection string. Target for --target AzureDocumentDb, source for --target Cosmos.Yes
--database-id <String>Cosmos database name (per-account Cosmos safely reuses 'CentralDatabase' for every tenant).No
--target <DbProvider>Which side is the migration target: AzureDocumentDb (forward) or Cosmos (reverse / rollback).Yes
--dry-runCount + sample only; do not write to the target. No --target side data is touched.No
--batch-size <Int32>Documents per write batch.No
--include-deletedAlso copy soft-deleted documents. Default false — matches the platform's default read shape.No
--customer-slug <String>The tenant's slug (= ConfigOptions.CustomerSlug), used as the vCore database name on the shared cluster where each tenant is a peer database. Required and declarative — there is no fallback to --database-id, so a tenant is never silently migrated into the shared Cosmos name (PRD-2789).Yes
--containers <String[]>Restrict migration to these container names (space- or comma-separated). Default: all source containers. Diagnostic-oriented — useful for re-migrating a single slice.No
--mode <CosmosCopyMode>Forward (--target AzureDocumentDb) only. copy (default; online, checks every page as written) | delta (changes since --marks-file; moves the marks) | reconcile (delete target docs gone from the source) | verify (exact counts + parity sample).No
--marks-file <FileInfo>JSON file of per-container _ts marks. copy and delta set a mark per completed container; delta reads it first. Required for delta and --resume (copy only).No
--parity-sample <Int32>verify: documents per container to compare field by field.No
--source-ru-per-second <Nullable1>`Forward only: RU/s ceiling for reads on the Cosmos source, shared by all workers; halves when Cosmos throttles and recovers slowly. Default: 25% of each container's provisioned throughput. 0 = uncapped.No
--resumeContinue a copy that stopped part way, from the progress file next to --marks-file. A stopped delta is simply run again.No
--diff-file <FileInfo>Write one JSON line per document that differs after it was written (container, id, partition key, path, both values).No
--no-verify-on-writeSkip reading each written page back from the target. Only for a throwaway copy.No
--scan-allreconcile: scan keys in every container, even where the counts already match.No
--workers <Int32>copy/delta: pages written and checked at once. The source RU cap is shared by all of them.No
--expect-deletes <String[]>reconcile: the deletes you expect per container, as Container=N (space- or comma-separated); N is the target − source count the refusal prints. Any other number refuses before deleting. Unlisted containers expect 0.No

Examples ​

bash
# Forward migration (Cosmos -> vCore), dry-run first
  central migrate tenant \
    --cosmos-connection-string "AccountEndpoint=..." \
    --vcore-connection-string "mongodb+srv://..." \
    --target AzureDocumentDb --dry-run

  # Forward migration, actual write
  central migrate tenant \
    --cosmos-connection-string "AccountEndpoint=..." \
    --vcore-connection-string "mongodb+srv://..." \
    --target AzureDocumentDb

  # Reverse (rollback): vCore -> Cosmos
  central migrate tenant \
    --cosmos-connection-string "AccountEndpoint=..." \
    --vcore-connection-string "mongodb+srv://..." \
    --target Cosmos
